## 1. 目标、研究主张与边界

### 1.1 总体目标

形成完整研究闭环：

**公开轨迹训练 → 风险评估 → 多来源联合定位 → 一致性修复 → 有限预算验证与选择 → 实际执行与结果评价。**

拟检验的论文主张：

> 利用行为与来源证据选择有限范围的干预，能否在相同成本下减少安全违规，并保留更多正常任务？

三个候选创新点分别是：

1. 多来源协同风险的预算化联合定位。
2. 风险传播依赖下的状态一致性、任务保持型修复。
3. 决策不确定性驱动的干预验证预算分配。

第二点为核心，第一点和第三点为配套方法。不能因为实现了三个模块就宣称形成了三个已验证创新。

### 1.2 已确认的实施范围

- 使用现有公开数据训练，允许在现有 AgentDojo 任务上重执行验证干预。
- 使用可配置的 OpenAI 兼容 API，支持远端服务或兼容的本地推理服务。
- 首期实现三个创新点的可运行原型，并具备公开基准小规模验证能力。
- 修复限于外部内容的工作副本、可见摘要、缓存内容和待执行参数。
- 不修改已经提交的文件，不撤销已经发生的外部操作，不依赖隐藏思维链。
- 首期威胁聚焦外部内容注入引起的未经授权披露。
- 攻击者可控制约定的外部内容，不能控制可信用户目标、工具定义、防御配置和评测实现。
- 不训练大型生成模型，不引入强化学习或自动在线更新作为首期依赖。

### 1.3 兼容与安全边界

- 保留现有命令、检查点格式和 `SafetyRuntime` 的语义。
- 新流程使用独立配置、任务标识和结果目录，旧校准文件不能用于新策略。
- 新流程默认是研究执行模式，不能自称生产安全认证。
- 未知状态、缺失标签、未执行分支必须保持 unknown/null，不补为安全或成功。
- 权限、可信目标和工具参数硬约束不能被低风险分数覆盖。
- 不通过修改可信目标、伪造审批、设置虚假的 sandbox 标志使候选通过检查。

## 3. 架构、公共接口与数据契约

### 3.1 三类状态严格分离

**执行记录：** 追加保存实际发生的动作、观察、版本变化和修改记录。不能把历史动作改成没有发生过，也不能删除其真实副作用证据。

**工作上下文：** 供智能体继续生成动作的可修改视图。每次清理生成新版本，并关联原始内容、补丁及来源。

**评测答案：** 攻击目标、隐藏任务元数据、官方评分和最终结果，由实验运行器持有。控制器、检测器、过滤器和候选选择器不得读取。

清理后必须重新生成候选动作。旧候选与旧后续轨迹不能继续作为新执行结果。

### 3.2 新代码组织

主要新增代码放在 `agent1/research/`。模块按职责组织，不要求每个概念都拆成一个文件：

| 模块 | 职责 |
| --- | --- |
| `contracts` | 公共类型、序列化和版本化契约 |
| `corpus` / `training` | 数据审计、划分、终局风险训练 |
| `scoring` | 本地风险模型与内容检查器统一接口 |
| `lineage` / `localization` | 证据关系与联合来源搜索 |
| `repair` | 生成补丁、失效派生内容、重生成请求 |
| `verification` / `scheduler` | 候选检查、预算分配与选择 |
| `controller` | 执行前闭环、版本检查和决策 |
| `adapters` | 内存环境、兼容 API、AgentDojo |
| `experiments` | 对照、消融、统计与结果导出 |

配置放在 `configs/research/`，测试归入 `tests/`，新增研究说明归入 `docs/`。不要修改 `build/lib/` 等构建副本。

### 3.3 最小公共类型

| 类型 | 必要信息 |
| --- | --- |
| `DecisionContext` | 可信任务、当前可见历史、工作上下文版本、候选动作、状态摘要 |
| `EvidenceGraph` | 来源片段、可见派生内容、候选参数及关系；边的证据来源和可信程度 |
| `RepairPlan` | 唯一方案 ID、处理对象、补丁、需重生成内容、适用状态摘要 |
| `VerificationResult` | 硬检查结果、风险评分、任务保留评分、成本、失败原因 |
| `DecisionResult` | 放行、修复后放行或暂停；选中方案、执行摘要和决策依据 |
| `EpisodeOutcome` | 实际任务与攻击结果、成本、完整性、合成标志；仅供评价 |

- 候选方案由独立 ID 标识，同类干预允许有多个候选。
- 原样放行也是显式候选。
- 输入和输出均记录格式版本，持久化使用 JSON/JSONL，不使用不可信 pickle。
- 类型不携带 API 密钥，也不把原始敏感内容无差别复制到摘要报告中。
- `VerificationResult` 的评分不等于实际 `EpisodeOutcome`，两者不得共用字段冒充。

### 3.4 适配器边界

环境适配器提供：

- `observe`：返回当前公开可见状态。
- `propose`：在当前工作上下文上生成候选动作。
- `fork`：创建隔离状态副本，用于受控实验或环境确实支持的检查。
- `apply_working_view`：应用版本化上下文补丁，不改写真实执行历史。
- `commit`：验证状态与动作摘要，执行确切动作并更新记录。

官方评分通过独立评测接口提供，不能附加在上述在线接口的返回值中。

API、环境及评分适配器均应可注入测试替身；测试替身的结果明确标记，不能进入正式报告。

## 4. 三个创新点的首版算法

### 4.1 预算化联合来源定位

1. 按段落或结构化字段切分外部内容，生成稳定片段 ID，保留来源、位置和时间。
2. 根据当前候选动作的可达关系筛选来源；单纯时间先后只能标记可见性，不能标记为因果依赖。
3. 搜索单来源及最多三来源组合。候选扩展交替考虑预测风险下降和共同影响同一参数的关系，避免只保留单来源高分项。
4. 使用分层束搜索，去重后按稳定 ID 打破平局；每种大小的集合均有被考察的机会。
5. 局部评分时同步生成对应工作视图并使相关派生内容失效。保留“仅遮蔽原文”作为消融。
6. 局部评分只用于候选筛选；重新生成动作和完整闭环结果才用于判断实际干预效果。

默认参数：

```yaml
max_sources: 8
max_group_size: 3
beam_width: 4
max_local_score_queries: 32
```

输出候选集合、评分变化、搜索开销和证据路径。不得将其自动命名为已验证的因果来源。

### 4.2 状态一致性与任务保持型修复

1. 将依赖关系分为“明确复制/确定性变换”与“可能相关”。LLM 推测只能形成后者。
2. 对选中的来源集合计算受影响范围，处理相关可见摘要、缓存片段与待执行参数，保留无关正常内容。
3. 来源过滤器返回定位补丁，不自由改写可信任务、政策和工具定义。
4. 脱敏只使用当前可见信息和可信配置，不能通过隐藏攻击目标寻找要删除的字段。
5. 清理或失效完成后，从更新后的工作上下文重新生成候选动作。
6. 不能可靠局部修复时，退回更大范围的工作上下文重生成；仍不符合约束则暂停。
7. 保留真实工具调用、返回及副作用事实，工作视图必须维持工具调用/返回结构一致性。
8. 提交前再比较状态版本、工作视图版本及候选摘要。任何变化都使旧方案失效。

首版算子：来源片段过滤、受影响派生内容重生成、待发送参数脱敏及有限组合。

每个来源集合最多生成两类方案，每次决策最多六个修复候选。只声称候选集合内的较小修改，不声称全局最小修复。

### 4.3 预算感知的验证与选择

验证分层：

1. **确定性检查**：参数格式、允许修改范围、可信目标完整性和状态一致性。
2. **本地评分**：提供风险排序；不同任务训练的评分应保留语义标签，不混成已校准的统一概率。
3. **API 检查**：使用独立、版本固定的提示评估残余风险与任务信息保留程度。检查器只能返回结构化判断，不能执行工具或改变权限。

调度流程：

- 必要检查通过的候选先取得一次验证结果。
- 将剩余预算优先给风险接近阈值、候选排名接近且结果分歧较大的方案。
- 首版启发式使用“评分分歧 ÷ 决策边界距离 ÷ 预计调用成本”；加正数下限避免除零，对评分尺度归一化。
- 排名接近时，在当前最佳候选和最有竞争力的候选之间分配预算；平局稳定排序。
- 首次验证前没有可估计的经验分歧，使用显式初始探索项；不得将缺失分歧当作零。
- 每候选最多验证三次。重复结果只表示检查器稳定性，不自动视为独立统计样本。
- 选择通过硬检查且符合冻结风险阈值的候选，并优先考虑任务保留评分和修改成本。
- 预算耗尽后，只能选择已完成必要检查的候选，否则暂停。

阈值、分歧权重和成本权重在开发数据上确定，并在测试前冻结。调度分数是启发式，不称为置信区间或已证明的信息增益。

清理、重生成和验证的全部 API 调用计入防御成本。本地评分次数单列。提供固定、随机和最高风险优先的同预算基线。

## 5. 数据、标签与模型训练

### 5.1 数据来源及首期分工

- ASSEBench：首期开发语料，分别保留 safety/security 标签定义。
- ATBench：外部测试用途，先核对发布版本、结构和重叠轨迹。
- LinuxArena：首期完成数据审计和独立评测准备，不将 side-task-success 无条件并入其他数据集的 unsafe 标签。
- AgentDojo：现有任务上的闭环验证，以及开发划分中允许采集的重执行结果。

数据来源：

- https://github.com/Astarojth/AgentAuditor-ASSEBench
- https://huggingface.co/datasets/AI45Research/ATBench
- https://huggingface.co/datasets/eval-aware/linuxarena-trajectories

固定实际使用的版本、来源、许可证信息和校验和。公开数据中的生成或模拟内容必须按原始来源描述，不能统称为真实生产日志。

### 5.2 数据审计

- 修复并测试 `content` / `contents` 等 schema 差异，不能静默跳过全部记录。
- 记录读取、接受、跳过、错误、类别及独立组数量。
- 检查同一任务、重复轨迹、攻击变体和修复变体的跨集合泄漏。
- 剔除模型输入中的评分解释、终局标签、隐藏攻击目标等答案字段。
- 当 label 定义不一致时，分别训练或分别报告，不强制合并。
- 工具参数、观察和事件顺序必须按实际语义对齐；工具结果不能回填到它产生之前的候选输入。
- 长轨迹策略在配置中固定并报告截断覆盖；不得在关键证据被丢弃后仍声称完整轨迹评价。

### 5.3 新增终局风险监督任务

新增 `trajectory_outcome` 任务，复用现有时序、关系图和融合编码思想，增加独立的终局分类头与检查点任务标识。

- 允许用已有轨迹前缀预测该记录的最终标签。
- 该目标是“最终轨迹被判为不安全”，不是“当前动作已经违规”或“首次风险发生时间”。
- 每条轨迹的训练权重归一化，避免长轨迹因前缀多而占据更大权重。
- 前缀抽样规则和随机种子固定，训练、验证、校准和测试按原始任务组隔离。
- 不把原 `weak` 标签转换成伪造的 exact/interval/formation 标签。
- 原有时间与风险形成任务保持独立，只有真实对应标签才能训练其输出。
- 不使用未训练或标签不足的旧效用头作为可靠任务完成预测。

新增任务的 checkpoint 应记录标签语义、数据版本、输入特征版本、种子、组划分和训练任务。不允许把新任务权重载入旧任务并伪装为兼容。

### 5.4 可选的开发集配对结果微调

在 AgentDojo 开发任务上获得真实配对执行结果后，可增加 `continuation_outcome` 任务用于干预排序：

- 原方案和修复方案必须来自同一起始快照。
- 保留后续执行策略、模型版本和采样设置。
- 标签来自实际终局，而不是风险模型预测。
- 缺失分支不补标签；单次重放不宣称总体因果效应。
- 测试任务的分支结果只供评价，不能用于训练、调参或在线选方案。

接入要求：

- 在工具执行前接入控制器；工具输出进入工作上下文时保留来源。
- 对多工具调用按确定顺序逐一评估，前一动作改变状态后重评估后续动作。
- 复制环境和上下文，避免候选验证修改主执行分支。
- 不能把完整未来重放及官方评分作为在线控制器的候选选择捷径。
- 官方任务完成与攻击成功判定由独立实验运行器调用。
- 确认官方评分布尔值的真实含义，防止把 attack success 与 security success 取反。
- 覆盖上游运行器重试行为，防止暂停后被隐藏重试绕过；所有重试及成本均记录。
- 基准任务与攻击变体清单在观察测试效果前固定，保留失败与中断任务。

### 6.2 兼容 API 客户端

实现统一 `LLMClient`，使执行器、过滤器和检查器支持独立模型配置。只要求当前任务需要的文本、结构化输出和工具调用能力，不依赖特定提供商的隐藏推理输出。

建议环境变量契约：

```text
AGENT1_LLM_BASE_URL
AGENT1_LLM_API_KEY
AGENT1_ACTOR_MODEL
AGENT1_SANITIZER_MODEL
AGENT1_VERIFIER_MODEL
```

过滤器与检查器模型可在配置中显式复用执行模型。未配置时不得猜测模型名或付费服务。

- 默认串行，配置超时，最多两次传输重试，全部尝试计费。
- 不支持的模型参数明确报错或经能力配置省略，不能静默改变实验设置。
- 检查器与过滤器输出使用严格 schema；输出非法即记为失败，不以自由文本猜测成功。
- 密钥不写入实验文件、异常日志、配置快照或命令示例。
- 测试默认使用 fake provider，不隐式发送付费请求。

### 6.3 预算与缓存

- 单次决策提供四、八、十二次防御 API 调用预算档位，并配置 token 上限。
- 真实运行必须提供模型、全局调用上限和 token 上限；若提供单价，再执行金额上限。
- 缺少必要配置时不启动付费运行，仍可完成离线测试与模拟验证。
- 缓存键绑定输入、上下文版本、模型、提示版本、采样设置和种子。
- 明确区分新采样、缓存命中和传输重试；缓存返回不能充当独立重复样本。
- 比较算法时同时报告实际调用成本与逻辑请求量；避免缓存先后顺序让某个方法获得不公平成本优势。
- 保存结构化决策、内容引用、必要补丁和成本账本，避免重复保存完整输入。

## 7. 命令、配置和产物

### 7.1 待实现的命令组

在现有 CLI 增加 `research` 命令组，提供：

| 命令 | 功能 |
| --- | --- |
| `audit-data` | 检查数据 schema、标签、重复与分组 |
| `prepare` | 生成新任务的版本化数据及 manifest |
| `train` | 训练终局风险模型或开发集 continuation 模型 |
| `evaluate` | 离线风险评价，不自动拟合测试阈值 |
| `run` | 运行模拟或显式配置的公开基准闭环 |
| `compare` | 按冻结实验清单运行对照和消融 |

所有命令显式使用配置和输出目录。以下为待实现的目标调用形式，不表示当前已存在：

```bash
.venv/bin/python -m agent1 research audit-data --config configs/research/data.json --output artifacts/research/audit
.venv/bin/python -m agent1 research prepare --config configs/research/data.json --output data/research_v1
.venv/bin/python -m agent1 research train --config configs/research/train.json --output artifacts/research/train_seed101
.venv/bin/python -m agent1 research evaluate --config configs/research/evaluate.json --output artifacts/research/offline_eval
.venv/bin/python -m agent1 research run --config configs/research/smoke.json --output artifacts/research/smoke
.venv/bin/python -m agent1 research run --config configs/research/agentdojo.json --output artifacts/research/agentdojo_smoke
.venv/bin/python -m agent1 research compare --config configs/research/experiment.json --output artifacts/research/comparison
```

示例配置中的数据路径、模型和 checkpoint 使用明确占位或 null，并在运行前校验；不要填入看起来可用但并不存在的文件。

### 7.2 配置内容

- 数据来源、revision、校验和、标签语义和固定组划分。
- 模型任务、特征设置、训练种子与 checkpoint。
- 来源搜索参数、修复候选限制、工作上下文处理规则。
- 阈值、候选排序和预算调度参数。
- API 模型、端点引用、超时、调用和 token 限制。
- 基准任务清单、攻击清单、重复次数及对照方法。

配置应有 schema/类型验证，并将去除密钥后的完整生效配置随实验保存。

### 7.3 输出

每个运行目录至少包含：

- `manifest.json`：输入、实现、模型、提示、基准及配置版本。
- `decisions.jsonl`：逐决策候选、补丁、验证及选择记录。
- `episodes.jsonl`：逐任务真实结果、终止原因、完整性及合成标志。
- `costs.jsonl`：调用、token、重试、缓存和延迟账本。
- `summary.json`：聚合指标与样本量。
- `report.md`：对照、限制、失败模式及可复现命令。

训练产物另存 checkpoint 与训练记录。默认拒绝覆盖已有输出；若提供 resume，只能恢复配置和输入摘要匹配的运行。

## 8. 分阶段实施与交付

### 阶段 1：数据与公共契约

- 新增公共类型、配置验证、结果 manifest 和成本账本骨架。
- 修复公开数据 schema 兼容，完成重复与标签审计。
- 实现终局风险训练和独立 checkpoint 标识。
- 保留原事件时间训练与弱标签隔离。

验收：真实样本可审计和转换；离线训练、保存、加载和评价链路运行；泄漏与错标签测试通过。

### 阶段 2：一致性修复

- 实现不可变执行日志、版本化工作上下文和证据关系。
- 在内存环境加入源头已清理但派生待发送内容仍受影响的验证场景。
- 实现局部过滤、派生内容失效、参数脱敏与重生成。
- 实现状态摘要绑定和重复提交防护。

验收：源头过滤与传播一致性修复产生可区分的实际结果；无关任务内容保留；所有场景明确标记 synthetic。

### 阶段 3：联合定位与验证调度

- 实现有限预算集合搜索、交互对照和小规模穷举参考。
- 实现候选验证队列、调度器、成本约束与兜底。
- 实现固定、随机、最高风险优先基线及相应消融。

验收：相同预算口径下可比较；不会越过预算或使用隐藏评分；输出可解释失败记录。

### 阶段 4：API 与 AgentDojo

- 接统一 API，完成格式、超时、失败和成本测试。
- 接 `workspace` 任务、执行前控制器与独立官方评分。
- 在配置、凭据和预算齐全时，运行少量正常与攻击任务的端到端验证。

验收：任务确实在公开基准环境中执行，结果来自官方判定；主状态与候选副本隔离；暂停不被隐藏重试绕过。

若缺少外部配置，交付完整离线代码和精确运行步骤，标注 live validation 未执行，不宣称完成真实接入验收。

### 阶段 5：对照实验与文档

- 冻结开发配置后运行对照、消融、跨任务和成本比较。
- 记录真实失败和负结果，按任务组统计不确定性。
- 完善 README、研究运行说明与所有入口的 help。

在 `docs/RESEARCH_IMPLEMENTATION_STATUS.md` 中持续记录各阶段完成状态、实际测试命令、结果及未完成原因，便于另一轮 Codex CLI 接续工作。

## 9. 测试与研究验收

### 9.1 必须覆盖的行为测试

1. 旧命令、检查点和准入约束保持原语义；现有测试无回归。
2. `content` / `contents` 两种 ATBench 结构可处理，空导入明确报错。
3. 单来源清理无效但联合清理有效的模拟案例被覆盖。
4. 源头已清理而派生内容仍危险时，一致性修复能够更新派生内容。
5. 无关正常内容和真实执行日志保持完整。
6. 修改隐藏攻击目标或评分对象，不改变同一公开输入下的在线决策。
7. 未来观察和终局解释不能进入当前候选输入。
8. 旧状态方案、修改后的候选和重复 commit 被拒绝。
9. 未知依赖、格式错误、API 超时、预算耗尽均产生明确、可统计结果。
10. 修复后从新状态生成和执行后续行为，不拼接旧后续轨迹。
11. 主环境、候选副本、上下文版本和缓存相互隔离。
12. 新采样、缓存、传输重试和多候选共享调用的账本正确，不重复计量或漏计。
13. 多工具调用顺序与暂停语义正确。
14. 测试结果、配对分支和同任务变体不得泄漏到训练及调参。

### 9.2 对照与消融

至少实现以下可组合的本项目基线：

- 无防御。
- 高风险直接阻断。
- 固定清洗。
- 单来源处理。
- 同预算随机来源组合。
- 来源过滤，但不更新派生内容。
- 全部工作上下文重生成。
- 固定验证预算。
- 完整方法。

小规模穷举只作为离线搜索参考，其实际成本单列，不与在线方法假装同成本。未复现的 CausalArmor、AttriGuard 等不能以同名方法输出虚构结果。

### 9.3 指标

- 安全：官方攻击成功率、明确语义下的违规率、干预后残余风险。
- 效用：正常任务完成率、攻击下合法任务完成率。
- 成本：调用量、token、金额（可得时）、延迟、本地评分次数和修改范围。
- 泛化：按未见任务、工具或攻击划分的表现，报告实际覆盖范围。
- 稳定性：多种子或多次采样；按独立任务组统计区间。
- 完整性：超时、异常、暂停、缺失评分和未完成任务分别列出，不能全部计为安全成功。

只有存在可靠首次违规位置时，才评价相对于实际事件的提前预警；终局标签不能替代时间标签。

### 9.4 完成标准

首期成功标准是：流程真实、接口完整、标签无泄漏、成本可核对、结果可复现。

- 工程测试通过不等于模型有效。
- 小规模公开基准 smoke 不等于已验证顶刊级性能。
- 模型分数降低不等于实际修复成功。
- 全部暂停造成的零攻击成功率必须同时显示任务效用损失。
- 新完整策略若要获得统计校准，需在独立组上重新执行和校准；现有固定策略二项界不能自动扩展为自适应攻击或分布漂移保证。

## 10. 最终交接格式

执行完成或遇到确实需要外部输入的阻碍时，输出：

1. 各阶段已完成和未完成事项。
2. 主要实现与接口变化。
3. 实际运行的测试、离线实验和公开基准实验，附结果路径。
4. 配置、数据、模型与 API 的缺项及其影响。
5. 可直接复制执行的下一步命令，不能引用原开发机器路径。
6. 当前证据能支持的结论及不能支持的主张。

不得把未运行的命令描述为通过，不得为了完成清单而生成伪造测试结果、基准结果或安全认证。
